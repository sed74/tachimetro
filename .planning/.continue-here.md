## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Worktree SUMMARY.md loss | After a worktree-isolated `gsd-executor` finishes, its `SUMMARY.md` is intentionally left **uncommitted** in the worktree (the orchestrator commits docs, not the executor). If you merge the worktree branch and then `git worktree remove --force` without first copying that uncommitted file out, it is gone — untracked files do not travel through a git merge. This happened once this session (plan 01 of quick task 260902-qr8); the SUMMARY had to be reconstructed after the fact from the merge diff and the executor's final report. | advisory | Before `git worktree remove`, always `cp` any `*-SUMMARY.md` under the worktree's `.planning/quick/.../` or `.planning/phases/.../` path out to the corresponding path in the main checkout. The official `/gsd:quick` and `/gsd:execute-phase` workflows already do this via their documented "rescue" step (or `gsd-sdk query worktree.cleanup-wave`) — do not skip it when doing the merge by hand. |
| Concurrent human edit to master during a worktree agent run | The user pushed a real commit straight to `master` (`app/build.gradle.kts` version bump, `69de1e2`) while a `gsd-executor` was running in an isolated worktree branched off an older `HEAD`. The next executor spawned in this session had to notice its worktree was behind and `git merge --ff-only master` before proceeding, or it would have silently overwritten the version bump and the prior plan's fixes on merge. | advisory | When spawning a worktree-isolated agent right after telling the user "you handle X yourself," expect the user to act concurrently. After such an agent returns, diff its branch against current `master` before merging, not just against the base it was spawned from. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
