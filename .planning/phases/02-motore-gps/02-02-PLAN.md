## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google Play Services (OS process) → GpsSpeedProvider | Trusted OS-level location API delivering `Location` (contains precise lat/lng + speed) into the app process |
| GpsSpeedProvider → rest of app | The class boundary where sensitive raw location must be reduced to non-identifying derived speed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-ID | Information Disclosure | GpsSpeedProvider.kt handling of raw `Location` (lat/lng) | mitigate | `SpeedState.Reading` carries only `Int` km/h — raw lat/lng never crosses the class boundary by construction. No `Log.*` of `Location` objects; any debug logging prints only derived `kmh`. Verified by acceptance criterion "no `Log.` of a Location object appears in the file". |
| T-02-EP | Elevation of Privilege | Permission handling in GpsSpeedProvider | accept/mitigate | GpsSpeedProvider does NOT request or re-check permissions and adds no manifest changes; it relies solely on MainActivity's Phase-1 `ACCESS_FINE_LOCATION` guard (single source of truth). `@Suppress("MissingPermission")` documents this contract rather than duplicating the check. `PRIORITY_HIGH_ACCURACY` works with fine-only permission — no coarse/background scope added. |
| T-02-D | Denial of Service (self, battery) | LocationCallback lifecycle | mitigate | `removeLocationUpdates` lives solely in `callbackFlow`'s `awaitClose {}`; combined with Plan 03's `repeatOnLifecycle(STARTED)` collection, updates stop exactly when the app is not visible — no leaked callback / background GPS drain (Pitfall 2). |
| T-02-V | Input Validation (data quality) | mapSpeedToKmh accuracy/hasSpeed filters | mitigate | Poor-accuracy readings dropped (D-05) and rounding/noise-floor applied (D-03/D-04) so spurious GPS spikes cannot surface as a wrong speed — a data-quality control, unit-tested in Task 1. |
