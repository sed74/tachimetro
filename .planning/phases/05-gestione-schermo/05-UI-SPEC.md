## Layout Contract (Android-specific, replaces generic component inventory)

One new element this phase: `keepScreenOnSwitch`, positioned bottom-left, mirrored vertically to the top-left MAX area (D-02). `messageText`, `unitText`, `retryButton`, `maxSpeedText`, `resetMaxButton` are unchanged from Phase 3/4 — this phase does not touch their constraints, autosize, or styling.

| Element | Requirement |
|---------|-------------|
| `keepScreenOnSwitch` (new) | `SwitchCompat` — single widget carrying its own label via `android:text` (baked-in text, no separate `TextView`), mirroring the one-widget-per-row pattern already used for `resetMaxButton` (D-01: "etichetta breve — non testo cliccabile"). |
| `keepScreenOnSwitch` position | Bottom-left corner, symmetric to the top-left MAX area (D-02). `layout_constraintStart_toStartOf="parent"` + `layout_constraintBottom_toBottomOf="parent"`, mirroring `maxSpeedText`'s `Start`/`Top` constraints on the opposite vertical edge. `wrap_content` width/height — not autosize, fixed-size secondary control. |
| `keepScreenOnSwitch` visibility | **Always `VISIBLE`** — never `GONE`, in every app state (ready, reading, searching, permission denied, permission denied permanently). This differs from `unitText`/`maxSpeedText`/`resetMaxButton`, whose visibility is tied to GPS/permission state: the screen-on preference is state-independent and must remain reachable at all times (D-03 — "sempre visibile... anche montato su un supporto in movimento"). Do not add any conditional visibility logic for this widget. |
| `keepScreenOnSwitch` checked state on launch | Reflects the persisted preference (or the charging-state-derived default on first launch — see CONTEXT.md D-04/D-05 for the behavioral rule; this is a data/behavior concern, not a visual one). Set the switch's checked state in `onCreate()` before the first frame draws, same "no flash" timing discipline as `updateMaxArea()` in Phase 4, so the toggle never visibly jumps from one state to another after launch. |
| `keepScreenOnSwitch` interaction | Tap toggles immediately — no confirmation, no intermediate state, standard `SwitchCompat` tap/drag behavior. Applies `FLAG_KEEP_SCREEN_ON` and persists the preference synchronously with the visual toggle (CONTEXT.md D-06/D-07) — the visual switch position must never be out of sync with the actual window flag state. |
| `keepScreenOnSwitch` touch target | Minimum 48dp height — set `android:minHeight="48dp"` explicitly (default `SwitchCompat` intrinsic height is smaller than 48dp; do not rely on the default, same accessibility floor rule as `retryButton`/`resetMaxButton`). |
| `keepScreenOnSwitch` tint (track/thumb) | Must stay within the existing black/white palette — do NOT let the widget fall back to the AppCompat theme's default `colorControlActivated`/`colorAccent` (typically a blue/purple hue), which would introduce an undeclared third color. Override `app:thumbTint` and `app:trackTint` with grayscale-only `ColorStateList` resources (see Color section below) so the switch reads as pure monochrome, consistent with UI-02. |
| Window insets (`keepScreenOnSwitch`) | Must apply the same `OnApplyWindowInsetsListener` pattern as `applyMaxAreaWindowInsets()`/`applyUnitTextWindowInsets()` in `MainActivity.kt`, mirrored for the bottom-left corner: add live `systemBars`/`displayCutout` **bottom** and **left** inset on top of the XML base margins (`applyScreenSwitchWindowInsets()` or equivalent name), so the switch never renders behind the navigation bar or a bottom/left-side display cutout in either orientation. Do not reuse `unitText`'s or `maxSpeedText`'s listener instance — insets differ per corner. |
| Overlap check with `retryButton` | `retryButton` is horizontally centered (`Start`/`End` both `toStartOf`/`toEndOf` parent) and vertically floats in the space below `messageText` — it is not flush to the absolute bottom edge in most states. `keepScreenOnSwitch` sits at the absolute bottom-left. No overlap is expected given `retryButton`'s centered horizontal position, but verify visually at the execution checkpoint in both orientations with the denial message showing (longest-text state) — if a conflict appears, it is an execution-time layout fix, not a contract change. |
| `messageText`, `unitText`, `retryButton`, `maxSpeedText`, `resetMaxButton` | Unchanged from `03-UI-SPEC.md`/`04-UI-SPEC.md` — no modifications this phase. |
| Animations | None. No layout transitions, no `TransitionManager`, no property animators on the switch toggle beyond `SwitchCompat`'s own built-in thumb-slide (a platform-native, non-optional widget behavior, not an app-authored animation) — consistent with UI-04. |
| Icons/graphics | None — the switch uses only its built-in thumb/track shapes with tint overrides, no custom icon (UI-04). |

## Color

Unchanged two-color palette from Phase 3/4 at the semantic level — this phase adds grayscale tint variants (not a new hue) for the switch's checked/unchecked states.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%+) | `#000000` (`@android:color/black`) | Full-screen background — unchanged |
| Secondary (30%) | Not applicable — no secondary surface exists by design (UI-04) | — |
| Accent (10%) | `#FFFFFF` (`@android:color/white`) | Reserved for: `messageText`, `unitText`, `retryButton` label, `maxSpeedText`, `resetMaxButton` label (existing, Phase 3/4) **plus** `keepScreenOnSwitch` label text and thumb tint (new, this phase) — same single accent color, no new hue introduced |
| Switch track tint (grayscale variant of accent, not a new color) | Checked: `#80FFFFFF` (white, 50% alpha) — Unchecked: `#33FFFFFF` (white, 20% alpha) | `keepScreenOnSwitch` track only, via a new `res/color/switch_track_tint.xml` `ColorStateList`. Both states are alpha variants of the existing white accent on the existing black background — this is explicitly NOT a third color; it exists solely to make the ON/OFF state legible at a glance (D-01) without introducing the AppCompat theme's default blue/purple `colorControlActivated`. |
| Switch thumb tint | `#FFFFFF` (opaque white) in both checked and unchecked states — thumb position (left/right), not thumb color, communicates ON/OFF | `keepScreenOnSwitch` thumb only, via a new `res/color/switch_thumb_tint.xml` `ColorStateList` (or a single flat `app:thumbTint="@android:color/white"` if no state variation is needed — prefer the flat form unless the checker flags a legibility issue with a single opaque thumb against both track states) |
| Destructive | Not applicable — toggling the switch is a fully reversible preference change, not a destructive action; no confirmation dialog, no warning color (CONTEXT.md D-06: immediate apply, no gate) |

Accent reserved for: `messageText`, `unitText`, `maxSpeedText`, `retryButton` text, `resetMaxButton` text, `keepScreenOnSwitch` label text and thumb — never introduce a third hue in this phase. The track tint values above are alpha-only variants of white/black, not a new color.
