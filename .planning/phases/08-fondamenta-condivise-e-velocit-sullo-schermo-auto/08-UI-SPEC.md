# Phase 8 — UI Design Contract

> Visual and interaction contract for the Android Auto (Car App Library) speed screen. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Domain note (read first):** This phase is a Car App Library screen (`androidx.car.app`), not a web/mobile touchscreen UI. There is no shadcn/Tailwind design system, no custom fonts/colors, and no pixel-level layout control — the Android Auto host renders all template chrome, typography, spacing, and day/night theming. This contract therefore fixes the **content, hierarchy, states, and copy** the app controls, and explicitly marks host-controlled dimensions as such rather than inventing values that don't apply. Where the standard UI-SPEC template asks for tokens that don't exist in this domain (spacing scale, hex colors, shadcn registry), the table is kept for consistency but filled with "host-controlled" / "not applicable" plus the reasoning, per `08-CONTEXT.md`'s explicit decisions (D-00 through D-10).

## Content Contract (replaces "Spacing Scale" — no pixel grid in this domain)

There is no app-controlled spacing scale: the host lays out all template chrome, padding, and margins. The equivalent control this phase has is **content structure and character budget** inside the single `Row`:

| Content slot | Maps to | Rule |
|--------------|---------|------|
| Primary value | `Row` title | Speed number only (e.g. `"87"`), no unit appended — mirrors phone's `messageText` showing digits only (D-01) |
| Unit label | `Row` secondary text/subtitle | Always `"km/h"`, shown paired with the primary value, mirrors phone's separate `unitText` (D-01) |
| Template-level title/branding | **None** | No app name or branding text inside the template screen (D-03) — if the Car App Library requires a non-empty header to pass internal validation, use a header action with no text (e.g. app-icon-only) rather than a text title. This is distinct from the Android Auto app-list entry, which does show `R.string.app_name`/`ic_launcher` as expected (D-04) — the "no title" rule applies only inside the screen content, not the app list. |
| Icon inside the Row | **None** | No icon on the speed row — text only, consistent with the project's "no unnecessary graphic element" philosophy (PROJECT.md Constraints) |

Exceptions: none.

## Typography (host-controlled — content hierarchy declared instead of sp/weight)

| Role | Host-controlled sizing | App-controlled content |
|------|------------------------|-------------------------|
| Primary value (speed digits / "Ricerca segnale...") | Host renders `Row` title at its own large/prominent size — no custom sp value obtainable | Digits only when reading (e.g. `"87"`); full replacement text `"Ricerca segnale..."` when searching/no-signal (see States) |
| Secondary label (unit) | Host renders `Row` subtitle/secondary text smaller than the title | Fixed literal `"km/h"`, shown only in the Reading state |
| Line height / weight | Not exposed to the app | not applicable |

No autosize logic is implemented by the app for this screen (unlike the phone's `TextViewCompat.setAutoSizeTextTypeUniformWithConfiguration` in `MainActivity`) — the host owns text scaling for template content.

## Color (host-controlled — day/night handled automatically)

| Role | Value | Usage |
|------|-------|-------|
| Dominant / Secondary / Accent | host-controlled | Standard templates render with the host's own day/night theme; the app declares no custom color and gets automatic light/dark switching for free (FEATURES.md — "Day/night theme on the car screen... effectively free if using standard templates"). No action required from this phase. |
| Destructive | not applicable | No destructive actions exist on this screen (see Copywriting Contract) |

Note: this means the phone's black-background/high-contrast visual identity (v1.0-v1.1) is **not** reproduced pixel-for-pixel on the car screen — this is an accepted, documented trade-off of the POI/template path (D-00a), not a regression to fix in this phase. Visual *equivalence* (large, legible, high-priority content) is preserved via the content contract above; visual *identity* is not achievable without Surface access, which was explicitly rejected (PITFALLS.md Pitfall 1).

## States

Reuses the existing `SpeedState` sealed model unmodified (`Searching`, `Reading(kmh, deltaMeters)`, `NoSignal`) via the shared, Application-scoped `GpsSpeedProvider.state: StateFlow<SpeedState>` (D-00b) — no new state model for content purposes.

| State | Source | Content shown |
|-------|--------|----------------|
| Reading | `SpeedState.Reading(kmh)` | Row title = `kmh.toString()`, Row secondary text = `"km/h"` |
| Searching / NoSignal (unified) | `SpeedState.Searching` OR `SpeedState.NoSignal` | Row title/text = `"Ricerca segnale..."` (single line, no unit shown) — mirrors `MainActivity.updatePlaceholder()`, which already unifies both branches under one message (MainActivity.kt:373-378) |
| Permission not yet granted | out of scope for this phase | Explicitly deferred to Phase 9 (AA-04, `CarContext.requestPermissions()`) per `08-CONTEXT.md` domain boundary. This spec does not define car-screen copy for this state — inventing UX here risks conflicting with Phase 9's design. Planning/execution for Phase 8 must still ensure `SpeedScreen` cannot crash if reached before permission is granted (defensive-only; no explicit UX contract from this document). |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary value (Reading) | The speed number as plain digits, e.g. `"87"` — no leading zeros, no unit suffix (unit is separate, see Content Contract) |
| Unit label (Reading) | `"km/h"` (fixed, always paired with the primary value) |
| Searching / no-signal state | **`"Ricerca segnale..."`** — exact text, locked by D-02. Deliberately shorter than the phone's `R.string.searching_gps_signal` ("Ricerca segnale GPS...") — truncates only "GPS". Requires a **new** string resource, distinct from `searching_gps_signal`. Suggested identifier (Claude's Discretion per `08-CONTEXT.md`, not locked): `car_searching_gps_signal`. |
| Android Auto app-list label | Reuses existing `R.string.app_name` = `"Tachimetro"` (unchanged) — this is the app-list entry, not in-screen branding; do not confuse with the "no title inside the template" rule (D-03) |
| Primary CTA | **None.** No interactive elements on this screen — consistent with "no menu, no interaction" philosophy and explicit milestone Out of Scope ("Pulsanti interattivi o schermata impostazioni sullo schermo auto") |
| Empty state | Not applicable — the Searching/NoSignal state above is this screen's only degraded state; there is no separate "empty data" concept for a live speed readout |
| Error state | Not applicable in this phase's scope — permission-denied/error messaging belongs to Phase 9 (AA-04), deferred per domain boundary above |
| Destructive confirmation | None — no destructive actions on this screen (max speed / distance reset stays phone-only, explicitly out of milestone scope per REQUIREMENTS.md "Out of Scope") |

## Refresh Cadence & Quota Verification (car-app-library-specific — no equivalent in the standard template)

This is the phase's highest-risk design constraint (SC4, Pitfall 2) and is captured here because it directly determines whether the content contract above can be delivered at the required cadence.

| Aspect | Decision |
|--------|----------|
| Target cadence | **1 Hz**, identical to the phone, implemented from the start — no preventive throttling (D-05) |
| Refresh mechanism | `SpeedScreen` collects the shared `GpsSpeedProvider.state` inside `repeatOnLifecycle(STARTED)` (same pattern as `MainActivity`, Pattern 2/ARCHITECTURE.md) and calls `Screen.invalidate()` on each emission to rebuild the template. No separate car-side timer — GPS's own 1 Hz ticker already paces this (Pattern 4). |
| Quota risk | Non-Surface templates enforce a hard **5-templates-per-task** host quota; whether same-type/same-content refreshes (only the number changing) are exempt indefinitely is undocumented (STACK.md, PITFALLS.md Pitfall 2) |
| Verification protocol | AVD emulator + Desktop Head Unit (DHU) with Developer Mode debug overlay, **5-10 minutes** of continuous simulated 1 Hz refresh (D-08, D-09 — deviates intentionally from PITFALLS.md's "real phone required" assumption for this specific quota check only). Automated where possible (script/instructions to launch AVD + DHU + count refreshes), final pass/fail confirmation is a **human checkpoint** (D-10), consistent with this project's existing on-device verification discipline. |
| Gate status | This verification is a hard **gate** before treating 1 Hz refresh as final for the milestone (D-06) — not a nice-to-have check |
| Mitigation if quota exhausted | Throttle refresh **on the car side only** (e.g. every 2-3s); the phone stays at 1 Hz unchanged. This requires **explicitly renegotiating SC3** ("stessa cadenza del telefono, senza salti") with the user — not a silent compromise (D-07). Do NOT fall back to reconsidering the Surface/NAVIGATION path (explicitly rejected option). |
