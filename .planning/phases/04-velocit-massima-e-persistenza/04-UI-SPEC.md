## Layout Contract (Android-specific, replaces generic component inventory)

Two new elements added this phase, mirroring the existing top-right `unitText` pattern on the top-left (D-01). `messageText` and `retryButton` are unchanged from Phase 3 — this phase does not touch their constraints, autosize, or styling.

| Element | Requirement |
|---------|-------------|
| `maxSpeedText` (new) | Top-left corner, symmetric to `unitText` (D-01). `layout_constraintStart_toStartOf="parent"` + `layout_constraintTop_toTopOf="parent"`, mirroring `unitText`'s `End`/`Top` constraints exactly. `wrap_content` width/height (not autosize — secondary element, fixed size per Typography table below). |
| `maxSpeedText` content | Label + number combined in one string, e.g. "MAX 120" (D-02) — new format string `max_speed_format = "MAX %1$d"`. Never shows bare number alone (avoids ambiguity with the dominant current-speed number in `messageText`). |
| `maxSpeedText` visibility | `GONE` by default in XML (`tools:visibility="visible"` for preview). Visible only when a max > 0 exists — either restored from disk at startup or set during the session (D-09). Never shows "MAX 0". |
| `resetMaxButton` (new) | Positioned below `maxSpeedText`, top-left zone, vertically chained under it (D-05) — `layout_constraintTop_toBottomOf="@id/maxSpeedText"`, `layout_constraintStart_toStartOf="parent"` (NOT centered across full parent width like `retryButton` — stays left-aligned under the label it controls). Does not share an ID, position, or visibility state with `retryButton`: `retryButton` only appears during permission-error states, `resetMaxButton` only appears during normal GPS-reading states with max > 0 — the two are mutually exclusive and never rendered together. |
| `resetMaxButton` visibility | `GONE` by default. Visible only when current max > 0 (D-03, D-09). Tied to the same condition as `maxSpeedText` — both show/hide together as a unit. |
| `resetMaxButton` behavior | Tap resets max to 0 immediately — no confirmation dialog, no undo (D-04). On reset: value in memory → 0, `maxSpeedText`/`resetMaxButton` revert to `GONE` (D-09 applies again post-reset since new max is 0), disk write happens immediately (D-08). |
| `resetMaxButton` touch target | Minimum 48dp height (Android accessibility minimum, same rule as `retryButton` in Phase 3). |
| Window insets (`maxSpeedText`) | Must apply the same `OnApplyWindowInsetsListener` pattern as `applyUnitTextWindowInsets()` in `MainActivity.kt`, mirrored for the start/left side: add live `systemBars`/`displayCutout` top and **left** inset on top of the XML base margins, so the MAX area never renders behind the status bar or a left-side display cutout in either orientation. Do not reuse `unitText`'s listener instance — write a parallel `applyMaxAreaWindowInsets()` (or extend the existing one to handle both start and end targets), since insets differ per side (start vs end). |
| Startup read timing | Read the persisted max value in `onCreate()`, before the first frame is drawn / before `permissionGranted` collection starts — so there is no visible flash of "MAX 0" or a hidden→visible flicker on launch (supports D-09). This is a Claude's-discretion item from CONTEXT.md; the above is the recommended timing to satisfy the "no flash" requirement implied by D-09. |
| `messageText`, `retryButton`, `unitText` | Unchanged from `03-UI-SPEC.md` — no modifications this phase. |
| Animations | None. No layout transitions, no `TransitionManager`, no property animators on show/hide of the MAX area (UI-04) — use plain `View.GONE`/`View.VISIBLE` toggles, consistent with existing `unitText`/`retryButton` pattern. |
| Icons/graphics | None — `resetMaxButton` is text-only ("Azzera massimo"), no icon (UI-04). |

## Spacing Scale

Declared values (dp, multiples of 4 — unchanged scale from Phase 3):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | not used this phase |
| sm | 8dp | Vertical gap between `maxSpeedText` and `resetMaxButton` — tighter than the 16dp used for the dominant `messageText`/`retryButton` pair, reinforcing that this is a compact secondary cluster, not a second focal point |
| md | 16dp | Horizontal margin (`marginStart`) and top margin (`marginTop`) between `maxSpeedText` and the screen edges — mirrors `unitText`'s existing 16dp top/end margins exactly, for left/right symmetry (D-01) |
| lg | 24dp | not used this phase |
| xl | 32dp | not used this phase |
| 2xl | 48dp | `resetMaxButton` minimum touch target height (Android accessibility floor, same rule as `retryButton`) |
| 3xl | 64dp | not used this phase |

Exceptions: `resetMaxButton` touch target is 48dp minimum height (Android platform minimum, same exception carried over from Phase 3). No other exceptions.
