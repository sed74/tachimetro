# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** Tachimetro is a native Android app (Kotlin, XML layouts, ConstraintLayout, no Jetpack Compose, no npm/shadcn). This contract adapts web-oriented template concepts to Android idioms: "px" → dp/sp, "component registry" → Android resource files (`colors.xml`, `strings.xml`, layout XML), "hover/focus states" → visibility states driven by GPS/permission state and reset taps. This document owns the **visual and copy contract** only — GPS filtering architecture, the `DistanceStore`/`reduceDistance()` domain logic, and the `SpeedState.Reading.deltaMeters` plumbing are owned by `07-RESEARCH.md` and the planner; this spec references them only where they affect what the user sees.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (speed digits, `messageText`) | 12–300sp (autosize uniform, 4sp steps) | 900 (black, via `textFontWeight="900"` + `textStyle="bold"`) | default (single line, `maxLines=1` while reading) — **unchanged** |
| Body (status/error messages, `messageText`) | 12–56sp (autosize uniform, 4sp steps) | 400 (regular) | default (multi-line wrap allowed) — **unchanged** |
| Distance value (`distanceText`) — **NEW this phase** | **32sp fixed** (D-03, locked — not autosize) | 400 (regular — matches `maxSpeedText`'s weight; D-03 only requires *bigger*, not bolder, than the 22sp MAX area) | default |
| Label (`unitText`, `maxSpeedText`) | 22sp fixed | 400 (regular) | default — **unchanged** |
| Label (`distanceUnitText`) — **NEW this phase, Claude's Discretion** | **16sp fixed** | 400 (regular) | default |
| Label (`keepScreenOnSwitch` text) | 16sp fixed | 400 (regular) | default — **unchanged** |

**Discretionary call — `distanceUnitText` size (16sp, not 22sp):** CONTEXT.md D-02 only locks the *pattern* ("separate small view, like `unitText`"), not an exact size. Two existing "small label" sizes already exist in the app (22sp, 16sp); reusing either introduces zero new type sizes. 16sp is chosen over 22sp because it creates a clearer big/small visual hierarchy against the new 32sp `distanceText` (2:1 ratio) and avoids visually blending the distance-unit label with the diagonally-opposite 22sp MAX-area label — reads unambiguously as one self-contained "number + unit" pair, matching D-01's literal examples ("850 m", "1,2 km"). Baseline-align `distanceText`/`distanceUnitText` (`app:layout_constraintBaseline_toBaselineOf`) — the standard Android pattern for number+unit pairs of differing size, avoids awkward vertical centering.

No autosize on `distanceText`/`distanceUnitText` — both are fixed-size, matching `maxSpeedText`/`unitText`'s precedent (only `messageText` autosizes).

## Component & Interaction Spec — Distance Area

*(Native-Android equivalent of the template's "Visuals" dimension — component inventory, layout, and state machine for the two new views this phase introduces, plus the behavior change to the existing reset button.)*

### New Android resources

| Resource | Name | Notes |
|----------|------|-------|
| View | `distanceText` (`TextView`, `@+id/distanceText`) | 32sp, white, regular weight, `maxLines="1"`/`singleLine="true"` (mirrors `maxSpeedText`'s single-line guard) |
| View | `distanceUnitText` (`TextView`, `@+id/distanceUnitText`) | 16sp, white, regular weight |
| String | `distance_meters_format`, `distance_km_format`, `unit_meters`, `unit_km` | See Copywriting Contract above |
| String (modified) | `reset_max_button` → `"Azzera"` | D-08 |

No new colors, drawables, or icons.

### Layout / positioning (bottom-right corner, DIST-01)

- `distanceUnitText`: `wrap_content`/`wrap_content`. `app:layout_constraintEnd_toEndOf="parent"` (16dp base `marginEnd`), `app:layout_constraintBottom_toBottomOf="parent"` (16dp base `layout_marginBottom`). This is the corner-anchored element — the one and only view in this group directly pinned to `parent`.
- `distanceText`: `wrap_content`/`wrap_content`. `app:layout_constraintEnd_toStartOf="@id/distanceUnitText"` (4dp `marginEnd` — the `xs` gap token), `app:layout_constraintBaseline_toBaselineOf="@id/distanceUnitText"` (typographic baseline alignment — no separate top/bottom constraint needed on this axis).
- Reading order left-to-right is "number then unit" (e.g. "1,2" then "km"), matching D-01's literal examples — `distanceUnitText` sits closest to the screen edge, `distanceText` chains off its start side. This clarifies/refines `07-RESEARCH.md`'s illustrative Pattern 5 code, which anchored the number view directly to `parent`; the layout above is the binding visual contract, the mechanism is at the executor's discretion as long as the rendered result matches.
- **Window insets (critical — do not skip):** one new function, `applyDistanceAreaWindowInsets()`, mirroring the three existing `applyXWindowInsets()` functions. Because `distanceText` is chained to `distanceUnitText` (not to `parent`) on both axes, **only `distanceUnitText` needs an inset listener** — `distanceText`'s position is fully derived through the constraint chain and needs no separate listener. This is simpler than the existing top-left MAX area (`applyMaxAreaWindowInsets()`, which must update two independently `parent`-anchored views). Add the live `systemBars`/`displayCutout` bottom+end inset on top of `distanceUnitText`'s 16dp base margins, called from `onCreate()` alongside the other three `applyXWindowInsets()` calls.
- Single adaptive layout only (no `layout-land` variant) — consistent with the Phase 3 decision.

### States

| State | Trigger | Visual |
|-------|---------|--------|
| Permission denied (`showDenied()`) | User has not granted GPS permission | `distanceText`/`distanceUnitText` → `View.GONE`. Mirrors the existing `maxSpeedText`/`resetMaxButton` hide in the same screen — the whole secondary-metrics UI hides while only the retry flow is shown. **Add this explicitly to `showDenied()`.** |
| Ready / Searching / NoSignal / Reading (any permission-granted state) | Default | `distanceText`/`distanceUnitText` → **always `View.VISIBLE`**, showing the current accumulated distance — including **"0 m" immediately after install or reset**, which is accurate and unambiguous (unlike the MAX area's hide-at-zero convention, where "MAX 0" before any reading would be misleading). This is a deliberate, documented divergence from `updateMaxArea()`'s pattern — not an oversight. |
| GPS fix accepted, `kmh >= noiseFloorKmh` (2.0) | New accepted fix with movement above the noise floor | `distanceText`/`distanceUnitText` update **instantly** to the new running total; format auto-switches m→km at the 1000m threshold (D-01). No animation. |
| GPS fix accepted, `kmh < noiseFloorKmh` (stationary, e.g. red light) | Vehicle stopped / GPS jitter | `distanceText`/`distanceUnitText` do **not** change (D-04 accumulation gate) |
| App backgrounded / GPS signal lost (`SpeedState.NoSignal`) | Foreground-only tracking (DIST-02) | `distanceText`/`distanceUnitText` remain visible showing the **last accumulated value**, frozen — no distinct "paused" visual state, no new status text (matches minimal-UI philosophy: silence, not a new indicator) |
| Reset tap ("Azzera") | User taps `resetMaxButton` | `distanceText`/`distanceUnitText` reset **instantly** to "0 m" (no animation, no confirmation) — simultaneously with the MAX area hiding (`currentMax` → 0). Both stores persisted to disk immediately. |

### Transitions

- **All visibility changes are instant `View.VISIBLE` ↔ `View.GONE`, no fade/slide/crossfade** — matches the existing `updateMaxArea()` pattern and the app-wide constraint that the charging icon's fill animation is the **only** animation permitted anywhere in the UI (PROJECT.md v1.1 exception). This phase adds **zero new animation**.
- Reset is immediate and unbatched: no debounce, no confirmation dialog, no delay before the on-screen text and the persisted value both update (matches existing Phase 4 max-reset precedent).

### Adaptive format logic (D-01)

Below 1000m: whole meters via `distance_meters_format` ("%1$d") + `unit_meters` ("m") — e.g. "850" + "m".
At/above 1000m: one-decimal km via `distance_km_format` ("%1$.1f") + `unit_km` ("km") — e.g. "1,2" + "km" (comma on it-IT locale, via `getString()`).
Branch decision uses the raw (unrounded) meters value; a value like 999.6m still rounds to "1000" in the meters branch rather than "1,0" in the km branch (Pitfall 5 in `07-RESEARCH.md`) — accepted as a ~1-meter edge case, not blocking.

### Reset Button — existing component, behavior extended (MAX-04)

- **Label:** `"Azzera massimo"` → `"Azzera"` (D-08). Same `resetMaxButton` id, same position (top-left, unchanged — no relocation despite now controlling two diagonally-opposite areas).
- **Action:** single tap zeroes `currentMax` (existing behavior) **and** the distance total (new) in the same click handler — one persisted write per store, both immediate, no confirmation.
- **Visibility rule — discretionary refinement:** `resetMaxButton.visibility` changes from "visible only when `currentMax > 0`" to **visible when `currentMax > 0 OR currentDistance > 0`**. Rationale: since the distance area is now always-visible independent of the MAX area's hide-at-zero state, the reset action must stay available whenever *either* metric has something to reset (e.g. an edge case on first upgrade where `currentMax` is already >0 from a prior version but `currentDistance` starts fresh at 0, or vice versa in future edge cases). `maxSpeedText`'s own visibility rule (`currentMax > 0` → visible/hidden) is unchanged.
